# Reactive power service

Сервіс з'єднує API/WebSocket → `MainDataSignal` → координатор → актори
батарей/КГУ → `WriteMaster`. Квитанції запису повертаються координатору;
фактичний стан надходить через API.

## Налаштування та запуск

1. Скопіюйте `config/settings.ini.example` у `config/settings.ini`, задайте API host/port.
2. У секції `[General]` цього ж файла задайте `username` і `password`.
   Змінні середовища для авторизації не потрібні. `config/settings.ini` виключений із Git.
3. Перевірте три конфігураційні файли акторів:
   - `config/condensators.toml`: параметри батарей, `[actor]` — таймінги, `[target]` — ким керує;
   - `config/kgu.toml`: параметри КГУ, його адреса/регістри, режим і тренд потужності;
   - `config/auxiliary.toml`: адреса допоміжної установки і значення on/off.
   IP/регістри КГУ та допоміжної установки — приклади, замініть їх.
   Часові параметри акторів записуються числом секунд.
   `single_write = true` обирає Modbus 0x06, інакше використовується 0x10.
   Відсутній файл створюється з дефолтними значеннями; зіпсований файл
   спричиняє помилку запуску й не перезаписується.
4. Підписка й розбір JSON реалізовані в `src/transport/web_api_actor.rs`.
   Список підтримуваних тегів та їх зіставлення — у `MainDataSignal`.
   `462_condensators_state` поки виключено: `SubStationOneState` не формується.
   Відсутні/null/нечислові значення та API-маркер відсутності даних
   пропускаються; справжній числовий нуль передається.
5. Запускайте з кореня репозиторію: `cargo run` (без аргументів).

`main` відстежує завершення API-воркера і зупиняє решту задач.
Ctrl+C завершує програму без додаткових команд обладнанню та без очікування Enter.
При помилці запуску, завершенні воркера або паніці програма показує причину
та чекає Enter перед виходом із кодом 1. Очікування вводу відбувається
після зупинки Tokio. Якщо stdin закритий, програма завершується одразу.

## Передача керування

- Початковий режим — батареї.
- КГУ працює, тренд вниз, P ≤400 кВт: батареї отримують Q, допоміжна установка — on.
- КГУ працює, тренд вгору, P >420 кВт: допоміжна установка — off,
  батареї переходять до поступового вимкнення. Q отримують обидва актори.
- Після НОВОГО зчитування нульової маски реле Q отримує лише актор КГУ.
  Батареї далі отримують напругу/реле, але їхній Q-watchdog у резерві не викликається.
- Зупинка КГУ повертає керування батареям.

Поріг шуму тренду застосовується до кожної пари сусідніх вимірів. Різноспрямовані
зміни або дрібні зміни дають Stable. Розмір вікна/поріг — у `config/kgu.toml`.
Якщо м'яке вимкнення зупинилось через таймаут або Failsafe, координатор
не оголошує перехід завершеним без нульової маски реле.

`AuxiliaryStation` формує on/off команди. Без тега зворотного зв’язку її
фактичний стан невідомий; в острові/блекауті off повторюється за таймером.
Виключення тега з підписки саме по собі не вимикає генерацію команд установці.
`main.rs` створює один спільний лічильник ID для всіх команд.

## Перевірка

`cargo test --locked`

Контроль remote КГУ виконує окремий `RemoteActor`, незалежно від режиму
компенсації, потужності та стану двигуна. Після зчитування значення, відмінного
від 1, він формує запис 1 і повторює його за таймером, доки зчитування не
підтвердить 1. Квитанція доставки сама по собі не підтверджує значення.
Налаштування `remote_register` і `remote_retry` розміщені в корені `kgu.toml`.
До першого зчитування актор не формує команд; невалідні значення ігноруються.

## Блекаут та острів

`GridMonitor` отримує `MainP` (кВт) і `MainQ` (квар) **трансформатора**.
`GenActivePower` є окремим виміром КГУ й у визначенні острова не бере участі.
Теги трансформатора вже зіставлені: `TotalMiddlePower` → `MainP`,
`TotalMidleKVar` → `MainQ`. Напруга: `V1/V12_MidleVoltage` → `MiddleVoltage`
(значення очікується у вольтах).

Острів: обидва значення у включному діапазоні 0..15 протягом 10 секунд,
щонайменше 5 свіжих пар. При періоді 2 секунди це 6 пар від t=0 до t=10.
Одиничне значення за межами діапазону скидає накопичення. Повторні тики
без нових P/Q не зараховуються як виміри. Час отримання — локальний;
API-адаптер має відкидати застарілі/повторно відтворені дані джерела.

Блекаут: обидва виміри P і Q не оновлювалися протягом `analyzer_timeout` (за замовчуванням
10 секунд). Це також покриває втрату зв'язку; фізичну причину за такими
даними програма не відрізняє. Нечислові значення не оновлюють сторожа.

В обох режимах головним батареям формується нульова маска реле, допоміжній
установці — off. Плани регулювання скасовуються; Q не передається обом
регуляторам. Remote-актор продовжує контролювати 1. Вимкнення повторюється
через `off_retry`, доки відповідні зчитування не підтвердять off; квитанція
запису сама по собі не підтверджує фізичне вимкнення.

Свіжа пара поза малим діапазоном повертає нормальний режим. Якщо КГУ працює
понад 420 кВт, запускається передача йому керування; інакше — батареям.
Після блекауту самі малі значення не дозволяють вмикання: спочатку вони
мають знову підтвердити острів. Параметри — `[grid]` у `condensators.toml`.

## Логування без блокування Tokio

`init_logger()` один раз запускає два незалежні системні потоки:
`logger-console` для stdout та `logger-file` для файлових операцій.
Виклики логера лише форматують і передають повідомлення через `try_send`.
`tracing` API-воркера також використовує консольну чергу. Синхронного
fallback на stdout або диск із Tokio-задач немає.

Черги обмежені: консоль — 256 повідомлень, файл — 1024. При переповненні
повідомлення пропускаються, лічильники втрат зростають. Консоль повідомляє
кількість пропущених повідомлень після відновлення виводу; файловий потік
додає накопичені лічильники втрат і помилок до наступного успішного запису.
`event` залишається тільки в консолі; ERROR/WARNING/DEBUG — також у файлі.
Файл визначається датою події, навіть якщо запис відбувається після опівночі.
Потоки живуть до завершення процесу; очікування завислого stdout/диска
не додається до завершення Tokio. Черги при виході процесу не гарантують
повного збереження останніх повідомлень.

КГУ за замовчуванням працює в розрахунковому режимі (`use_carriage = false`):
за P КГУ, фактичною уставкою та похибкою Q обчислюється потрібна нова уставка.
`max_step_units = 1000` дозволяє всю потрібну корекцію за один запис у межах
шкали. Перед наступною командою актор чекає підтвердження та стабілізації.
Для старого режиму каретки можна встановити `use_carriage = true`.

Блекаут не визначається за мовчанням лише одного тега: якщо P незмінний,
але Q продовжує надходити (або навпаки), аналізатор вважається доступним.
Для підтвердження острова, як і раніше, потрібні свіжі пари обох вимірів.
Якщо API не надсилає навіть незмінні P/Q, потрібна окрема ознака доступності
аналізатора: самі повідомлення інших пристроїв не є його heartbeat.
