# Reactive power service

Сервіс з'єднує API/WebSocket → `MainDataSignal` → координатор → актори
батарей/КГУ → `WriteMaster`. Квитанції запису повертаються координатору;
фактичний стан надходить через API.

## Налаштування та запуск

1. Скопіюйте `config/settings.ini.example` у `config/settings.ini`, задайте API host/port.
2. Задайте облікові дані змінними середовища `API_USER` та `API_PASS`.
3. Перевірте `config/runtime.toml`: IP/порт/unit/регістри КГУ і допоміжної
   установки є прикладами, їх потрібно замінити. Шлях до конфігів рахується
   від поточної робочої теки. `single_write = true` обирає Modbus 0x06,
   інакше використовується 0x10.
4. Допишіть ДВІ заглушки в `src/transport/web_api_actor.rs`:
   - `subscription_message()` — JSON підписки;
   - `on_text_message_received()` — зіставлення тегів із `MainDataSignal`.
     Не надсилайте `None`, нечислові або відсутні значення як нулі.
5. Запускайте з кореня репозиторію: `cargo run -- config/runtime.toml`.

До заповнення заглушок API не готовий до роботи: `unimplemented!()` навмисно
викликає panic. `main` відстежує завершення API-воркера і зупиняє решту задач.
Ctrl+C завершує програму без додаткових команд обладнанню.

## Передача керування

- Початковий режим — батареї.
- КГУ працює, тренд вниз, P ≤400 кВт: батареї отримують Q, допоміжна установка — on.
- КГУ працює, тренд вгору, P >420 кВт: допоміжна установка — off,
  батареї переходять до поступового вимкнення. Q отримують обидва актори.
- Після НОВОГО зчитування нульової маски реле Q отримує лише актор КГУ.
  Батареї далі отримують напругу/реле, але їхній Q-watchdog у резерві не викликається.
- Зупинка КГУ повертає керування батареям.

Поріг шуму тренду застосовується до кожної пари сусідніх вимірів. Різноспрямовані
зміни або дрібні зміни дають Stable. Розмір вікна/поріг — у runtime.toml.
Якщо м'яке вимкнення зупинилось через таймаут або Failsafe, координатор
не оголошує перехід завершеним без нульової маски реле.

`AuxiliaryStation` — плейсхолдер генерації on/off команд; перевірка її
фактичного стану та автоматичні повтори ще не реалізовані.
`main.rs` створює один спільний лічильник ID для всіх команд.
